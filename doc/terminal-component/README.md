## 三条最重要的结论

1. **「所有命令都做 DOM 呈现」不可行。** 交互式程序（vim/less/top/ssh/sudo/进度条）
   在原理上没有 DOM 形态；命令长尾无界。Warp / Wave / cmux / VS Code 四家独立收敛到
   「真终端兜底 + 少量富化」。可行的是**分层覆盖**：L0 真终端 → L1 内容嗅探 →
   L2 高频白名单 → L3 可配置扩展。（`01` §4）

2. **不要为 GUI 重造终端模拟器。** Wave 后端把 PTY 裸字节直接落盘、零解析；
   cmux 的 OSC 解析交给 Ghostty 回调。我们现有的 `normalizeTerminalLayout`
   （约 160 行，三进三出）应删除，改为从 `xterm.buffer.active` 派生块内容。（`02` §3.1）

3. **「终端不友好」的解法可能不在终端里。** Wave 的 widgets 与 cmux 的自定义命令
   /自定义侧栏，两个独立项目收敛到同一答案：**给零命令入口**。
   这比继续打磨终端呈现更对症。（`02` §3.3）

## 决策记录

| 项 | 结论 |
|---|---|
| 文件/路径点击行为（2026-08-30 设计） | **块内预览**（复用 `TerminalRichContent.vue`）；目录就地展开为文件树 |
| 文件/路径点击行为（2026-08-31 实际落地） | 文件 = 块内预览 ✅；**目录点击暂只提示「是目录」**，就地展开文件树未做（用户核心诉求的残余 gap，见 `04-design.md` §11）；目录浏览由侧边文件树面板（C1）承担 |
| 预设命令 | **L1 + L2 都做**，分两批发布 ✅（批次 2 / 批次 3）；L2 参数转义在主进程按会话 shell 家族完成 |
| 命令补全数据源 | **未引入 withfig 庞大数据集**；历史补全打底 + 手写高频命令规格（`CommandCompletion.ts`），withfig（MIT）留作长尾覆盖的合规升级路径 |
| 终端是否拆为独立项目 | **暂不拆**；先做内部边界加固，稳定后转同仓 package（见 `05-roadmap.md` §5） |
| 是否使用 Warp 代码 | **不使用**（AGPL-3.0-only vs MIT）；只参照其产品形态，自行实现；`command-signatures-v2` 数据同样禁用 |
