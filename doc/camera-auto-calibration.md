# 相机自动标定：需求与实施规格

状态：测量链路（SSH 旁听 ttyS6）、自动恢复现场、单/双目标配置、表单基线直发（set_params 后等待 settle 重建数据流，不做回读核对）、连接自动读参填表单已实现并有单元测试覆盖；协议格式、回读通道与串口上报过滤规则已于 2026-09-10 在真机（192.168.3.14）实测/逆向确认。**2026-10 固件新增标定开关 `set_calibParam`**（1=全量上报、0=默认过滤、重启归 0）：现由人物信息观测统一管理，视频与自动标定共享观测，首个观测方开启时置 1、最后一个观测方退出时归 0；完全相同目标记录在解析层去重。**尚待真机验证**：2.0 m 双目标全流程、搜索方向的首次实机确认。真机验收完成前不得将标定结果视为已确认。

## 1. 设备事实（实测与逆向确认）

- 相机板 RK3566 / Ubuntu 20.04，业务程序 `appMain` 由 `myscript.service` 拉起（autostart.sh → update.sh 自更新 → appMain），SSH root@192.168.3.14:22。
- 对外网络面只有两个端口：**8080 命令协议**（`<IIH` 包头 + 16 字节子命令；子命令含 `read_version / read_params / set_params / start_follow / read_imu / bbox_draw / set_calibParam / read_calibParam`，纯请求-响应，无主动推送）与 **8554 RTSP**。
- **标定开关（2026-10 固件升级新增）**：`set_calibParam` 内容 `"1"`/`"0"` 文本。**1 = 串口全量上报跟踪目标**（解除下述 1.5 m 非跟随过滤），**0 = 默认过滤行为；设备重启后自动归 0**。Nav-Tools 在首次人物信息观测（视频或自动标定）开启时置 1、最后一个观测方退出时归 0；标定结束本身不再关闭全量上报，恢复核对清单在观测清理时显示开关项。
- **INSSEG 报文唯一出口是板载串口 `/dev/ttyS6`**（115200 8N1，发往底盘），网络侧不可得；只能经 SSH 用 strace 旁听 appMain 对 ttyS6 的 write。实测约 **47 Hz**。
- **串口上报列表有距离过滤（2026-09-10 真机实测 + 反编译 `classBBoxFilter` 确认）**：跟随目标（trackID=70000）无条件上报；其余目标仅当距离 ≤ 1.5 m 时上报（最多 4 个），且该 1.5 为编译内字面量（`getConfigMaxRecoDist` 无调用方，改 `deviceCfg.xml` 的 `maxRecoDist` 无效）。**RTSP 叠框画的是全部跟踪框、无此过滤**——因此"RTSP 看到 2 框、串口 num=1"是预期行为；标定开关置 1 后该过滤解除，>1.5 m 目标也可经 INSSEG 测量。
- **全量上报可能包含完全相同的重复目标**：2026-11 真机实测两个目标各重复一次，原始 `num=4` 而唯一 `trackId` 只有 2 个。`InssegParser` 按完整目标字段去重，`lastFrame`、视频显示和人数检查使用去重后的列表；同一 `trackId` 但字段冲突的记录保留并由后续身份检查拒绝，原始报文仍保留在 `rawLines` 供诊断。
- 报文格式（实测样本，字段顺序与 `InssegParser` 一致）：
  `$ESTAR,INSSEG,YYMMDD.HHMMSS.mmm,帧号,图号,num[,P_XX,]class,track,left,top,right,bottom,distance,azimuth,...*XOR`
- **参数回读通道存在**：8080 `read_params` 返回裸文本 `版本, height(m), fov, thetaOffset(°)`，实测 `2.1.0.250930seg15, 0.550,1.087,-21.500`。注意 **fov 为弧度**（62.292° = 1.087 rad），height/thetaOffset 单位与表单一致；跨通道核对仅对 thetaOffset/height，fov 只做同通道前后对比或按 deg→rad 换算校验。
- `set_params` 同步更新内存与 `deviceCfg.xml`（`distMeasure/height|vfov|thetaOffset`），并置 `do_update` 重建 INSSEG 发送线程——**写入后数据流会短暂中断**，属正常现象。
- strace 为 ptrace 附加，采样期间 appMain 全线程有可感知减速：仅限小车静止时使用。采样没有固定总时限，持续到主动停止、SSH 断开或采样进程异常退出；设备端监视 SSH stdin 的关闭并终止 strace，主动停止时核实 `TracerPid=0`、无残留进程。

## 2. 场景与已确认规则

- Nav-Tools 的 Camera Parameters（相机参数）窗口提供自动标定区域，保留手动命令功能。
- 小车停在 0 m 基准位置，标定过程中静止。
- **目标数目可选 1 或 2，每个目标独立配置参考距离与合格区间**；双目标时按“人员 1 方位”（左/右）把画面目标对应到配置序号。默认双目标：人员 1 在右侧 1.2 m、人员 2 在左侧 2.0 m。观测会开启固件全量上报，使 2.0 m 目标也可经 INSSEG 测量；开关开启失败或固件不支持时，仍受非跟随目标 ≤1.5 m 的过滤限制。
- 以布置距离为参考，不额外计算斜距；几何偏差计入验收偏移。
- 默认参数模板 `0.55,62.292,-21.5`；自动搜索只改变第三项 OFFSET，前两项锁定。不再配置固定步长，按实测偏差计算修正角，以 0.5 阻尼逐步收敛。
- 数据接入的相机 TCP 连接建立时（及窗口打开时已连接）自动 `read_params` 一次填充表单：height/OFFSET 直填，FOV 由弧度换算回角度；读取失败时 OFFSET 回退默认值 -20 并提示人工核对（height/FOV 保持表单现值），不新增手动按钮。
- `set_params` 永久生效，按持久配置修改管理；当前实现写入后等待设备重建数据流，不自动执行回读核对。
- 默认误差容忍度为 ±0.02 m；同一 OFFSET 下两个目标必须同时合格：1.2 m → 1.18～1.22 m，2.0 m → 1.98～2.02 m。不逼近中点。
- 用原始数值判定，浮点比较仅容许表示误差（回读核对容差 0.002，对应三位小数舍入）。

## 3. 数据链路

- **测量链路**：主进程 SSH 测量通道（ssh2）→ 随 SSH 生命周期管理的 `strace -f -q -y -p "$(pidof appMain)" -e trace=write -s 16384` → 主进程解码 strace 转义还原 ttyS6 文本流 → `InssegParser` 校验解析 → 标定引擎。不上传任何文件到设备。
- **控制链路**：工具栏数据接入的相机 TCP 连接（8080），承担 `set_params` 写入与 `read_params` 读取（连接建立时自动读参填表单）；标定期间独占，手动命令被禁止。
- 凭据：密码经 safeStorage 加密存储于主进程（渲染端不持久化明文），UI 可覆盖。
- 数据源中的 SSH 配置框按需读取已保存的密码，默认隐藏，点击眼睛图标可显示或隐藏；关闭配置框会清空渲染端的密码字段。快速打开配置框时等待共享的配置读取完成，避免密码字段被较晚返回的配置覆盖。连接卡片与配置框共用连接中状态，禁用重复提交；缺少必填配置时打开配置框，连接失败时保留原因并允许重试。
- 采样退出后的重连：观测订阅与 SSH 采样状态分别管理，仅复用正在连接或采样中的通道；采样停止或出错后，再次连接会清理旧通道并重新建立采样，保留视频、标定等已有订阅。固定 300 秒采样上限已取消；SSH 断开明确提示，采样异常退出显示退出码或信号。此前只检查观测订阅，导致采样已退出时点击连接仍返回旧错误状态。
- SSH 认证前断开立即返回错误；采样命令启动最多等待 5 秒，旧通道清理核查最多等待 3 秒，避免设备无响应时连接请求一直挂起。清理命令的进程匹配排除自身，核查没有取得结果时不会报告已清理成功。
- 所有连接卡片均提供连接/断开切换按钮，配置入口独立保留。共享 Retry 开启时，任一相机链路成功会取消其他连接中或出错的链路并立即重连；已连接正常的链路保持不动，手动断开的链路不自动拉起。RTSP 区分连接中与播放中，SSH 和观测重连使用代次隔离旧请求并保留原租约数，避免迟到成功覆盖新连接或断开时遗留通道。

## 4. 数据资格与人数限制

1. 去重后的检测结果中的人形数量与配置一致（1 或 2）；双目标与参考距离的对应关系由用户确认且采样期间稳定。
2. 报文完整、校验通过，数据新鲜（1.5 秒内）。
3. 人数与配置不符、数据中断、无效报文、身份切换或序号异常时：禁止写入、清空采样窗口、恢复后重新采样，超时停止并说明原因。**死循环防护（v1.7.9）**：双目标现场目标 flicker、测距波动反复超限或复验窗口反复失败时，引擎会无限「采样 → 暂停 → 恢复 → 重采」，期间既不写入也不失败（此前仅 maxDuration 全局超时兜底，表现为「标定不停但无任何动作」的静默循环）。现累计连续被打断的采样次数（同一暂停期间的重复触发只计 1 次），连续 10 次仍未取得参数写入或成功即判定失败并给出最近原因；每次成功写入参数将计数清零，正常的短暂干扰不受影响。
4. **`num` 语义已实测确认（2026-09-10）**：`num` 是过滤后的上报数，不等于画面内完整人形数——RTSP 可见 2 人而串口 `num=1` 已实测复现（远海报 2.0 m 被过滤）。**2026-10 固件已提供全量上报开关（`set_calibParam`）**：人物信息观测开启时置 1，>1.5 m 目标（如 2.0 m 双目标）可经 INSSEG 测量；开关未开启（固件不支持或开启失败）时仍按原过滤规则拒绝启动并说明。

## 5. 标定流程（已实现）

1. 用户开启人物信息观测：建立共享 SSH 测量通道并置 `set_calibParam=1` 全量上报，不写 height/FOV/OFFSET；视频播放也会独立申请同一观测。
2. 点击「开始标定」：
   - **确认全量上报已开启**：复用观测开关状态，不重复写开关；随后等待开关生效后的新一帧 INSSEG（47 Hz，正常几十毫秒）再做人数核对；
   - 表单即真值：把表单 height/fov/initialOffset 整组 `set_params` 下发作为搜索基线（不回读核对），并等待 settle 时长让设备应用参数、重建 INSSEG 流；
   - 手动 Reset 的基准 = 该表单基线（originalParams = 表单 height/fov/initialOffset）。注意：连接时已自动 `read_params` 填表单，正常流程下表单值即设备当前值。
3. 采样窗口评估：各目标中位数与波动（maxSpread）判定；两个目标同时合格进入独立窗口复验，复验通过即成功，不逼近中点。历史表的 Accepted 列固定在最右侧。
4. 未达标时按实测偏差计算下一 OFFSET：发送 → settle 等待 → 重新采样（不做回读核对；写入失败由发送超时/异常兜底，立即失败并停止自动写入）。
5. **结束与保留参数、清理现场**：
   - 失败/停止/成功均保持最后发送的参数，不再自动回写表单基线；只有用户手动点击 Reset Params 才恢复基线；
   - **全量上报保持开启**：标定成功/失败/停止本身不归 0，视频仍可显示人物信息；最后一个观测方退出时才恢复 `set_calibParam=0`，恢复核对清单显示开关项，恢复失败时提示设备重启后自动归 0；
   - **观测持续运行**：标定结束不拆除测量通道，只有人为「停止观测」或关闭窗口时才拆除 strace 并核查现场（strace 残留 / TracerPid 两项此时才转正），界面核对清单以 `…` 表示待核查项。
6. 异常兜底：SSH 使用 keepalive 检测失活，SSH exec 的 stdin 关闭时设备端看守进程终止 strace，父 shell 的退出清理同时回收看守进程；没有固定采样总时限。控制连接断开立即停止标定并保留最后参数；手动恢复参数失败时明确提示人工核实。

## 6. 搜索规则

- 测量偏远 → OFFSET 更负；偏近 → 趋近 0。以地平面几何关系将实测距离误差转换为角度修正量：`(atan(height / measured) - atan(height / target)) × 180 / π × 0.5`，不使用固定步长，也不把米制误差直接当角度相减。
- 双目标按误差超出各自容差的相对程度选择当前最需要修正的目标，迭代后重新检查所有目标；误差方向相反时判定无共同单调解并失败，不做平均抵消。
- 全程受限：OFFSET 安全范围、0.001° 参数分辨率、最大写入次数（≤30）、总时长（≤120 s）、重复候选拒绝。该策略已通过模拟样本单元测试，实机搜索方向与完整标定流程仍按第 8 节验收。

## 7. 脚本注入

相机参数窗口提供独立的脚本注入卡片（与测量源共用 SSH 配置与凭据存储，独立连接，可与观测并行）：

1. 选择本地 `.sh` 脚本（仅支持 shell），经 SFTP 上传到相机板 `/tmp/navtools_script_*`；
2. `chmod +x` 后以 `timeout <时限> bash <脚本>` 执行（时限 1~600 秒），stdout/stderr 实时进入消息组件；
3. 「停止」断开执行流并向远端 bash 发送 SIGTERM；
4. 结束后自动删除远端脚本，不留残留。上传/执行异常在界面状态徽章与消息组件中明示。
