# 相机自动标定：需求与实施规格

状态：测量链路（SSH 旁听 ttyS6）、`read_params` 回读闭环、自动恢复现场、单/双目标配置、OFFSET 基线自动同步（height/FOV 保留回读门控）、连接自动读参填表单已实现并有单元测试覆盖；协议格式、回读通道与串口上报过滤规则已于 2026-09-10 在真机（192.168.3.14）实测/逆向确认。**尚待真机验证**：搜索方向的首次实机确认。真机验收完成前不得将标定结果视为已确认。

## 1. 设备事实（实测与逆向确认）

- 相机板 RK3566 / Ubuntu 20.04，业务程序 `appMain` 由 `myscript.service` 拉起（autostart.sh → update.sh 自更新 → appMain），SSH root@192.168.3.14:22。
- 对外网络面只有两个端口：**8080 命令协议**（`<IIH` 包头 + 16 字节子命令；子命令仅 `read_version / read_params / set_params / start_follow / read_imu / bbox_draw`，纯请求-响应，无主动推送）与 **8554 RTSP**。
- **INSSEG 报文唯一出口是板载串口 `/dev/ttyS6`**（115200 8N1，发往底盘），网络侧不可得；只能经 SSH 用 strace 旁听 appMain 对 ttyS6 的 write。实测约 **47 Hz**。
- **串口上报列表有距离过滤（2026-09-10 真机实测 + 反编译 `classBBoxFilter` 确认）**：跟随目标（trackID=70000）无条件上报；其余目标仅当距离 ≤ 1.5 m 时上报（最多 4 个），且该 1.5 为编译内字面量（`getConfigMaxRecoDist` 无调用方，改 `deviceCfg.xml` 的 `maxRecoDist` 无效）。**RTSP 叠框画的是全部跟踪框、无此过滤**——因此“RTSP 看到 2 框、串口 num=1”是预期行为，1.5 m 外的目标无法经 INSSEG 测量。
- 报文格式（实测样本，字段顺序与 `InssegParser` 一致）：
  `$ESTAR,INSSEG,YYMMDD.HHMMSS.mmm,帧号,图号,num[,P_XX,]class,track,left,top,right,bottom,distance,azimuth,...*XOR`
- **参数回读通道存在**：8080 `read_params` 返回裸文本 `版本, height(m), fov, thetaOffset(°)`，实测 `2.1.0.250930seg15, 0.550,1.087,-21.500`。注意 **fov 为弧度**（62.292° = 1.087 rad），height/thetaOffset 单位与表单一致；跨通道核对仅对 thetaOffset/height，fov 只做同通道前后对比或按 deg→rad 换算校验。
- `set_params` 同步更新内存与 `deviceCfg.xml`（`distMeasure/height|vfov|thetaOffset`），并置 `do_update` 重建 INSSEG 发送线程——**写入后数据流会短暂中断**，属正常现象。
- strace 为 ptrace 附加，采样期间 appMain 全线程有可感知减速：仅限小车静止时使用，命令自带 `timeout 300` 兜底，结束时主动 pkill 并核实 `TracerPid=0`、无残留进程。

## 2. 场景与已确认规则

- Nav-Tools 的 Camera Parameters（相机参数）窗口提供自动标定区域，保留手动命令功能。
- 小车停在 0 m 基准位置，标定过程中静止。
- **目标数目可选 1 或 2，每个目标独立配置参考距离与合格区间**；双目标时按“人员 1 方位”（左/右）把画面目标对应到配置序号。默认双目标：人员 1 在右侧 1.2 m、人员 2 在左侧 2.0 m。注意双目标启动要求两人均在固件串口上报窗口内（非跟随目标 ≤1.5 m），超出窗口的目标无法经 INSSEG 测量。
- 以布置距离为参考，不额外计算斜距；几何偏差计入验收偏移。
- 默认参数模板 `0.55,62.292,-21.5`；自动搜索只改变第三项 OFFSET，前两项锁定。搜索大步长默认 1（粗调）、最小步长 0.2（精调，找到两侧边界后二分细化）。
- 数据接入的相机 TCP 连接建立时（及窗口打开时已连接）自动 `read_params` 一次填充表单：height/OFFSET 直填，FOV 由弧度换算回角度；读取失败时 OFFSET 回退默认值 -20 并提示人工核对（height/FOV 保持表单现值），不新增手动按钮。
- `set_params` 永久生效，按持久配置修改管理；每次写入后必须 `read_params` 回读核对。
- 允许偏差默认 +2～+6 cm；同一 OFFSET 下两个目标必须同时合格：1.2 m → 1.22～1.26 m，2.0 m → 2.02～2.06 m。`1.26 / 2.03` 即合格，不逼近中点。
- 用原始数值判定，浮点比较仅容许表示误差（回读核对容差 0.002，对应三位小数舍入）。

## 3. 数据链路

- **测量链路**：主进程 SSH 测量通道（ssh2）→ `timeout 300 strace -f -q -y -p "$(pidof appMain)" -e trace=write -s 16384` → 主进程解码 strace 转义还原 ttyS6 文本流 → `InssegParser` 校验解析 → 标定引擎。不上传任何文件到设备。
- **控制链路**：工具栏数据接入的相机 TCP 连接（8080），承担 `set_params` 写入与 `read_params` 回读；标定期间独占，手动命令被禁止。
- 凭据：密码经 safeStorage 加密存储于主进程（渲染端不持久化明文），UI 可覆盖。

## 4. 数据资格与人数限制

1. 完整检测结果中的人形数量恰好为 2；两个目标与参考距离的对应关系由用户确认且采样期间稳定。
2. 报文完整、校验通过，数据新鲜（1.5 秒内）。
3. 人数不为 2、数据中断、无效报文、身份切换或序号异常时：禁止写入、清空采样窗口、恢复后重新采样，超时停止并说明原因。
4. **`num` 语义已实测确认（2026-09-10）**：`num` 是过滤后的上报数，不等于画面内完整人形数——RTSP 可见 2 人而串口 `num=1` 已实测复现（远海报 2.0 m 被过滤）。在固件提供全量上报开关之前，>1.5 m 的目标无法经 INSSEG 测量，双目标同时标定不可用；1.5 m 内的场景可用单目标或双目标模式。

## 5. 标定流程（已实现）

1. 用户点击「开始观测」：建立 SSH 测量通道，只旁听、不写参数。
2. 点击「开始标定」：
   - `read_params` 回读门控：height/FOV 是几何标定常量（引擎不调它们、测距全靠它们），设备值与表单（fov 按角度换算）不一致时拒绝启动并显示双方数值，要求人工核对（该门控取代早期的人工确认复选框）；
   - OFFSET 基线不一致不再拒绝：按表单 initialOffset 自动 `set_params` 同步并 `read_params` 核对，再从初值开始搜索；
   - 记录启动回读快照作为恢复基准（originalParams = 表单 height/fov + 回读 thetaOffset，即自动同步前的设备原值）。
3. 采样窗口评估：各目标中位数与波动（maxSpread）判定；两个目标同时合格进入独立窗口复验，复验通过即成功，不逼近中点。
4. 未达标时二分/限步搜索下一 OFFSET：发送 → `read_params` 回读核对（不一致立即失败并停止自动写入）→ settle 等待 → 重新采样。
5. **结束与恢复现场（自动执行）**：
   - 失败/停止：自动回写标定前参数并 `read_params` 核对一致；
   - 成功：保持标定参数并回读核对一致；
   - **观测持续运行**：标定结束不拆除测量通道，只有人为「停止观测」或关闭窗口时才拆除 strace 并核查现场（strace 残留 / TracerPid 两项此时才转正），界面核对清单以 `…` 表示待核查项。
6. 异常兜底：SSH 断开时设备端 sshd 终止 exec 进程 + `timeout 300` 兜底；控制连接断开立即停止标定并提示人工核实；恢复流程执行期间断链时明确警告“参数需人工核实”。

## 6. 搜索规则

- 测量偏远 → OFFSET 更负；偏近 → 趋近 0。两侧同向越界按步长搜索，找到两侧边界后二分细化。
- 一者合格另一者不合格：调整后两者复验，不牺牲已合格目标。
- 误差方向相反：判定无共同单调解并失败，不做平均抵消。
- 全程受限：OFFSET 安全范围、最小步长、最大写入次数（≤30）、总时长（≤120 s）、重复候选拒绝。

## 7. 脚本注入

相机参数窗口提供独立的脚本注入卡片（与测量源共用 SSH 配置与凭据存储，独立连接，可与观测并行）：

1. 选择本地 `.sh` 脚本（仅支持 shell），经 SFTP 上传到相机板 `/tmp/navtools_script_*`；
2. `chmod +x` 后以 `timeout <时限> bash <脚本>` 执行（时限 1~600 秒），stdout/stderr 实时回显到界面；
3. 「停止」断开执行流并向远端 bash 发送 SIGTERM；
4. 结束后自动删除远端脚本，不留残留。上传/执行异常在界面状态徽章与输出框中明示。
