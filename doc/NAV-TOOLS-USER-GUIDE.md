适用版本：Nav-Tools 1.8.5（Windows）

安装包：[Nav-Tools-Windows-1.8.5-Setup.exe](../../../04-GNSS/中科院北斗所/2.1-测试软件-基础功能测试程序开发/Nav-Tools-Windows-1.8.5-Setup.exe)

## 1. 通用操作

### 1.1 进入应用

1. 打开 Nav-Tools，在应用选择器中选择 **Serial** 或 **GNSS**。
2. 点击工具栏的 **数据接入（Input）**。
3. 在“数据源配置”中选择文件、串口或网络，并设置解析方式。
4. 关闭弹窗后，在消息区、图表和右侧 Status View 中观察数据。

### 1.2 连接状态

底部左侧的连接开关表示当前数据源状态：

- 灰色：未连接。
- 橙色闪烁：正在连接，再次点击可取消。
- 绿色：已连接，再次点击可断开。

更换串口或解析方式前，建议先断开当前连接。

## 2. Serial：作为日志查看器使用

Serial 默认包含以下区域：

| 区域 | 用途 |
|---|---|
| 图表 | 将数值字段显示为实时曲线，单图最多 4 条；双图每图最多 4 条 |
| 消息 | 查看原始收发日志、过滤、搜索、暂停、置底和保存 |
| Status View | 显示解析后的实时指标，也可增加自定义计算指标 |
| Hex报文 | 配置设备读写指令，普通 HEX 调试也可直接在消息区完成 |

### 2.1 CSV 逗号数据

CSV 适合 `时间,纬度,经度,高程,卫星数,HDOP` 这类 GNSS 数值记录。

示例：

```text
12.50,31.297800,120.661900,55.20,12,0.90
12.75,31.297805,120.661915,55.24,13,0.85
```

操作步骤：

1. 在“数据接入 → 数据源配置 → 串口连接”中选择端口和波特率。
2. 数据格式选择 **结构化（Structured）→ CSV**。
3. 点击“确定”，消息区会持续显示 CSV 日志。
4. 打开“图表 → 配置”，将第 2、3、4 列加入曲线；需要观察第 5、6 列时，可替换现有曲线或使用双图布局。

解析规则：

- 每行按逗号拆分，字段键默认为列号 `1、2、3、4、5、6`。
- 示例中第 1 列是时间，第 2 列是纬度，第 3 列是经度，第 4 列是高程，第 5 列是卫星数，第 6 列是 HDOP；经纬度使用十进制度。
- 数值字段同时出现在 Status View 和图表的可选数据源中。
- CSV 表头主要用于文件批量导入；实时串口数据建议直接发送数据行。

### 2.2 自定义正则数据

当设备使用自定义帧格式时，用正则的命名捕获组为字段命名。

示例数据：

```text
@GNSS,12.500,31.297800,120.661900,55.20,12,0.90
```

示例正则：

长表达式在 PDF 中可能分行显示，粘贴到配置框时应合并成一行；也可直接复制交付目录中的 `serial-gnss-regex.txt`。

```regex
@GNSS,(?<time>[\d.]+),(?<latitude>-?[\d.]+),(?<longitude>-?[\d.]+),(?<altitude>-?[\d.]+),(?<satellites>\d+),(?<hdop>[\d.]+)
```

操作步骤：

1. 在数据格式中选择 **自定义（Custom）→ 正则表达式**。
2. 输入正则表达式，确认各命名捕获组能匹配对应数值。
3. 在“图表 → 配置”中选择 `latitude`、`longitude`、`altitude`、`satellites` 或 `hdop`。
4. 观察原始日志、实时指标和曲线。

提示：

- `(?<name>...)` 中的 `name` 就是图表和 Status View 中的字段名。
- 默认的 key/value 解析也支持 `time=1.2 latitude=31.2978 longitude=120.6619 altitude=55.2 satellites=12 hdop=0.9` 这类记录。
- 若消息区有数据但图表为空，先检查正则是否真正匹配，再检查显示格式是否误设为 HEX。

### 2.3 NMEA 文件回放

没有在线设备时，可使用现成 NMEA 文件回放。

示例文件：

```text
E:\BaiduSyncdisk\PROJ-GNSS\共有资料\测试与实验\测试数据样本库-ES\宝时得\模拟宝时得测试0213\2min\1\684K.nmea
```

操作步骤：

1. 打开“数据接入 → 文件输入”。
2. 输入上述文件路径。
3. 数据格式选择 **协议（Protocol）→ NMEA**。
4. 点击“确定”，消息区显示 GGA、RMC、GSA、GSV 等语句。
5. 根据需要使用时间轴、播放倍速和采样间隔。

该样本同时包含单点定位和浮点解记录，适合验证日志显示和定位指标更新。文件前部有少量空 GGA/RMC 语句，等待出现有效定位语句即可。

### 2.4 在 Serial 中绘制 NMEA 曲线

**NMEA 协议模式**用于解析和校验定位语句；它不会自动把 GGA 字段注册为 Serial 图表的数据源。要在 Serial 的“图表”组件中观察数值，请将文件输入的数据格式改为 **自定义 → 正则表达式**，从 GGA 语句提取数值。

可使用下面的表达式：

```regex
GGA,(?<utc>[\d.]+),(?<latitude>[\d.]+),[NS],(?<longitude>[\d.]+),[EW],(?<quality>\d+),(?<satellites>\d+),(?<hdop>[\d.]+),(?<altitude>-?[\d.]+),M
```

| 字段 | 含义 | 注意事项 |
|---|---|---|
| `utc` | UTC 时间 | 形如 `085735.30`，不是 Unix 时间戳 |
| `latitude` / `longitude` | NMEA 格式的纬度 / 经度 | 度分格式，不可直接当十进制度使用 |
| `quality` | 定位质量指示 | 数值含义见 NMEA 协议；不等于最终 RTK 精度 |
| `satellites` | 使用的卫星数 | 来自 GGA |
| `hdop` | 水平精度因子 | 越小通常越好 |
| `altitude` | 海拔高（正高），单位米 | 来自 GGA 高程字段，不是椭球高 |

操作步骤：

1. 按上一节选择文件，将播放倍速设为 `×5`，便于快速观察样本。
2. 将数据格式设为“自定义 → 正则表达式”，粘贴上面的表达式并确定。
3. 等待 GGA 数据进入，右侧 Status View 会出现 `altitude`、`satellites`、`quality` 等实时指标。
4. 打开“图表 → 配置”，布局选择“双图”。上图选择 `altitude`，下图选择 `satellites` 和 `quality`，应用配置。
5. 同时观察原始 NMEA 日志、两条图和 Status View。需要固定解状态、卫星分布或地图时，改用 GNSS 应用的 NMEA 协议解析，不要把这里的数值图表等同于完整 GNSS 解算。

若 Status View 没有这些字段，先检查语句是否包含有效的经纬度、N/S、E/W 和数值字段；样本中的空 GGA 不会产生曲线。

### 2.5 Status View 的使用

- 右侧 Status View 与图表共用解析后的数值字段，显示当前样本的实时值。
- 字段较多时可滚动状态区；拖动字段前的排序手柄可以调整顺序。
- 点击字段可编辑自定义指标，点击 **Add metric** 旁的加号可新增计算指标。
- 放大应用窗口或暂时关闭不需要的面板，能给日志、图表和状态区留出更多空间。录制时应保持右侧 Status View 在画面内，不要只展示图表。
- 修改数据源或解析方式后，旧字段可能需要清理。通过“清空控制台”和图表的清除按钮开始下一次演示。

### 2.6 原始日志工具

消息区提供以下功能：

- **过滤**：只显示符合当前解析规则的数据。
- **时间**：显示或隐藏接收时间。
- **置底**：自动跟随最新消息。
- **暂停**：停止界面更新，便于检查某一段日志。
- **搜索**：查找文本并上下跳转。
- **保存**：将当前日志保存到文件。
- **清空控制台**：清除当前日志，便于开始下一次测试。

## 3. Serial：HEX GNSS 接收机控制

### 3.1 打开 HEX 模式

1. 连接串口后，将消息区的显示格式切换为 **HEX显示**。
2. 将底部输入框左侧格式切换为 **HEX**。
3. 输入十六进制字节，字节之间使用空格分隔。
4. 点击发送按钮，或按 Enter。

发送记录显示为 `HEX ➡️`，设备返回记录显示为 `MSG ⬅️`。

### 3.2 GNSS 接收机演示协议

配套模拟器使用 5 字节帧：

```text
AA 55 CMD VALUE CHECKSUM
```

`CHECKSUM = AA XOR 55 XOR CMD XOR VALUE`，即前 4 字节逐字节异或。

| 操作 | 发送 | 应答示例 | 含义 |
|---|---|---|---|
| PING | `AA 55 01 00 FE` | `AA 55 81 01 7F` | 检查设备是否在线 |
| 开启 NMEA 输出 | `AA 55 02 01 FC` | `AA 55 82 01 7C` | 开启接收机 NMEA 输出，并返回状态 1 |
| 停止 NMEA 输出 | `AA 55 02 00 FD` | `AA 55 82 00 7D` | 停止接收机 NMEA 输出，并返回状态 0 |
| 读取 GNSS 状态 | `AA 55 03 00 FC` | `AA 55 83 05 0C 75` | 模拟浮点解（质量 5）、使用卫星数 12，校验值随状态变化 |

模拟器在应答后追加 CRLF，便于消息区按完整行显示。真实设备的帧格式和换行规则以设备协议为准。

本版日志可能连续显示 HEX 字节，例如 `AA550100FE`；这与表格中带空格的 `AA 55 01 00 FE` 等价。应答末尾还会显示 CRLF 对应的 `0D0A`。读取 GNSS 状态的应答为 6 字节，其他常规应答为 5 字节。

`START_NMEA` 会实际开启 GGA/RMC 的每秒播发，`STOP_NMEA` 会停止播发。消息区处于 HEX 显示时，这些 ASCII 语句显示为十六进制，以 `24 47 50`（`$GP`）开头；切换为 ASCII 可读原始 NMEA。模拟的浮点解仅用于教学，不代表接入了真实差分服务。

### 3.3 使用 Hex 报文组件发送指令

配套示例配置：[serial-hex-demo.json](../tmp/video/serial-hex-demo.json)。

1. 先按第 3.4 节运行 HEX 模拟器，并让 Nav-Tools 连接 `COM21`。
2. 打开 **Hex报文 → 配置 → 加载配置**，选择上述 JSON 文件。
3. 检查报文预览：报头为 `AA55`，校验为 **XOR**，从第 0 字节开始计算。
4. 本例不携带寄存器个数或长度字段。将“地址”字段用作命令码 `CMD`，将“功能码”字段用作 `VALUE`。
5. 点击“确定”保存，返回 Hex 报文组件。读参数页会出现 **PING、START_NMEA、STOP_NMEA、READ_GNSS_STATUS** 四个按钮。
6. 点击按钮发送指令，在消息区观察对应的 `HEX ➡️` 和 `MSG ⬅️` 记录。

本例是固定短帧，没有独立数据区，因此将四个触发命令集中放在“读参数”页，并将长度设为 0、关闭长度和寄存器字段。长度 0 表示不携带数据，并不表示不发送报文。示例仅检查原始 HEX 应答，不将应答映射为 Status View 指标；真实设备若需要周期读取和数值映射，应按其应答格式配置读取长度、数据类型和字节序。

命令与按钮对应关系：

| 按钮 | CMD | VALUE | 实际发送 |
|---|---|---|---|
| PING | `01` | `00` | `AA 55 01 00 FE` |
| START_NMEA | `02` | `01` | `AA 55 02 01 FC` |
| STOP_NMEA | `02` | `00` | `AA 55 02 00 FD` |
| READ_GNSS_STATUS | `03` | `00` | `AA 55 03 00 FC` |

配置保存于应用的 `motor-config` 本地设置中。修改真实设备协议前，建议先导出原有 JSON 备份。无需周期发送时，频率保持为空，不要误启动连续读取。

### 3.4 运行模拟设备

先准备虚拟串口对。本例中：

- Nav-Tools 连接 `COM21`。
- 模拟器连接 `COM22`。

以下命令在 Nav-Tools 项目根目录运行，四选一。若使用交付目录中的示例，先进入 `03-日志查看程序`，将命令中的 `tmp/video/` 前缀去掉，直接运行 `serial_device_simulator.py`。切换模式前，先停止旧模拟器，避免同时占用 COM22：

```bash
# GNSS CSV 周期播发
python tmp/video/serial_device_simulator.py --mode csv --port COM22

# 自定义 @GNSS 数据播发
python tmp/video/serial_device_simulator.py --mode regex --port COM22

# NMEA 定位语句播发
python tmp/video/serial_device_simulator.py --mode nmea --port COM22

# HEX 指令应答设备
python tmp/video/serial_device_simulator.py --mode hex --port COM22
```

自动录制时可追加 `--duration 180`，三分钟后自动退出，防止遗留进程长期占用串口。项目源码中的 `python tmp/video/recorder/verify-simulator.py` 可检查虚拟串口对的四种模式和 NMEA 开关行为；该命令在项目根目录运行，检查时两端端口均应空闲。

依赖：Python 3 和 pyserial。若未安装：

```bash
python -m pip install pyserial
```

使用结束后，停止模拟器并关闭对应串口，避免端口占用。

## 4. GNSS：串口定位数据

### 4.1 连接接收机

1. 在 GNSS 应用中打开“数据接入 → 串口连接”。
2. 选择接收机端口，例如 `COM5`，波特率按设备设置，常见为 `115200`。
3. 数据格式选择 **协议（Protocol）→ NMEA**。
4. 点击“确定”，等待 GGA、RMC、GSV 等语句进入。

建议先确认单点定位（SPP）正常，再配置差分注入。

### 4.2 主要面板

| 面板 | 用途 |
|---|---|
| GNSS 地图 | 显示定位轨迹和当前定位点 |
| GNSS 偏差 | 查看定位偏差、轨迹和当前解状态 |
| GNSS 信号 | 查看各星座卫星的 PRN、SNR、仰角和方位角 |
| GNSS 星空图 | 查看卫星空间分布 |
| 消息 | 查看 NMEA 原始语句 |
| Status View | 查看经纬度、高程、速度、卫星数和解状态 |

常见解状态包括：无效解、单点定位解、伪距差分、**浮点解**和固定解。浮点解表示 RTK 已生效，能否进入固定解还取决于卫星、遮挡、链路和接收机状态。

### 4.3 停止接收后的历元回看

串口或网络 NMEA/POS 输入停止、异常断开后，工具栏会显示本次接收数据的历史时间轴。拖动时间轴或双击 Deviation 的散点、地图轨迹点，可定位到对应历元，联动消息高亮、Sky Plot、Signals 和 Status View。卫星视图使用数据中实际包含的逐星信息。

接收期间暂停消息显示不会漏掉历史记录。相同数据源重连后恢复最新状态并接续历史；切换数据源或解析类型时开始新的数据集。历史回放不会重新打开设备，也不会改变真实连接状态；需要长期保留的数据可通过消息导出或日志记录保存。

## 5. CORS/NTRIP 差分注入

### 5.1 配置步骤

1. 保持 GNSS 串口数据源已连接。
2. 打开“数据接入 → 数据注入”。
3. 选择“网络连接”，协议选择 **NTRIP Client**。
4. 填写 CORS 地址、端口、挂载点、用户名和密码。
5. 开启“回传 GGA”，建议间隔 5 秒，让服务端获得接收机概略位置。
6. 点击“连接并注入”。

本视频演示配置：

```text
地址：140.143.212.42
端口：8003（CGCS2000，参考历元 2000.0）
挂载点：RTCM32_GRECJ2（5 星 16 频）
用户名：<填写自己的 CORS 账号>
密码：<填写自己的 CORS 密码>
```

端口选择：

| 端口 | 坐标框架 |
|---|---|
| 8001 | ITRF2014，参考历元 2020.0 |
| 8002 | WGS84（北京54/西安80） |
| 8003 | CGCS2000，参考历元 2000.0 |

密码只保留在本次会话中，不会写入本地配置。演示视频中的密码已掩码。

### 5.2 判断注入是否成功

重点检查注入页顶部状态：

- 状态为“已连接”。
- 转发目标为当前串口，例如 COM5。
- “接收”和“已转发”字节数持续增加。
- GGA 计数按设定间隔增加。

随后返回 GNSS 工作台，观察 FIX MODE 是否从单点定位解切换为浮点解，并在条件良好时进一步进入固定解。

## 6. 故障排查

| 现象 | 优先检查 |
|---|---|
| 串口不存在 | 设备是否松动或被其他程序占用；刷新串口列表后重新选择 |
| 消息区有 CSV，但图表为空 | 是否误设为 HEX 显示；第 2、3、4 列是否已加入图表配置 |
| 正则数据有日志但无指标 | 命名捕获组是否匹配、字段名是否拼写一致 |
| HEX 应答乱码 | 将消息区显示格式切为 HEX，并确认应答确实到达 |
| 模拟器无应答 | 检查帧长、异或校验和端口方向；本例协议为 5 字节 |
| 有 NMEA 日志但无定位指标 | 检查 GGA/RMC 是否有效、经纬度是否有效、解状态是否有效 |
| NTRIP 已连接但无转发字节 | 先连接串口数据源，再检查挂载点、账号、坐标框架和 GGA 回传 |
| SPP 正常但始终无浮点解 | 检查差分字节是否真正写入接收机，以及卫星数量、遮挡和链路稳定性 |
| COM5 突然消失 | 重新插拔设备，或改用现成 NMEA 文件回放 |

## 7. 相关应用补充

- **GNSS-Raw**：用于 RTCM3 和 RINEX 原始观测数据分析，不等同于实时 NMEA 面板。
- **GNSS-Lib**：通过统一的 GNSS 解算组件切换后处理（RTKPOST）与实时解算（RTKNAVI），使用 Open-GNSS 内核，并共享消息与 Deviation 组件展示解算记录、运行日志和定位轨迹。
- 内核构建产物、WASM 包名和同步方法见 [Open-GNSS 接入与同步](OPEN-GNSS-INTEGRATION.md)。
- 如果只需要快速查看设备日志和定位结果，优先使用 Serial 与 GNSS；需要原始观测质量分析或后处理时，再使用 GNSS-Raw 与 GNSS-Lib。
